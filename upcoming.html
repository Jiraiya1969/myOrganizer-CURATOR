CURATOR Planning Record

Planned Changes for Next Release

Updated On: October 19, 2026 at 8:48 AM EDT

What We're Working On

These are the improvements currently planned for the next CURATOR release. Development is still underway, so the final list may change before release.

CURATOR v2.5.0-beta.1 remains the current public release.

Changing

  • Organizer shows deferred CHD extraction in one TaskBar with verified-image counts, live worker extraction percentages, track-hash counts and separate verification. Images advance after their recorded track evidence matches; the phase has one completion, with progress and verification recorded in the run, detail and debug logs.
  • Organizer prepares deferred CDI images with one overall TaskBar, showing the current image, track-writing progress, verified tracks and elapsed time. Resumed work includes previously verified images and tracks, with one phase completion and detailed operation timing in the run, detail and debug logs.
  • Organizer pairs output preparation, recovery checks, catalogue saving and run completion with elapsed-time status indicators and single completion messages. Output creation and catalogue-file writing retain measured TaskBars; detailed batch activity remains in the run, detail and debug logs.
  • Platform Preparation, DAT Discovery, Reference Library preparation, File Discovery, Scan Preparation, Matching, DAT Validation, Collection Assembly, Completeness and Organizer show an animated status indicator with elapsed time during database work without a TaskBar. Existing TaskBars and single completion messages are preserved, with starts, outcomes and elapsed times recorded in the run, detail and debug logs.
  • Completeness shows paired announcements and elapsed-time status indicators during collection checks and output planning, with one completion per operation. Result counts, plan totals and readiness are recorded in console output and logs.
  • Collection Assembly pairs announcements with preparation, saving assembly decisions and updating source records. It reports confirmed set and review counts with elapsed time, distinguishes inferred media groups, and describes assembly decisions in its summary.
  • DAT Validation pairs preparation and saving announcements with the actual work, reports file and review counts with elapsed time, and uses summary labels that cover all content types.
  • Matching pairs announcements with loading, identity checks, comparison, optional disc checks and saving results. It uses wording for all content types, reports when additional disc checks are unnecessary, and preserves one completion per operation.
  • Reference Library preparation uses wording that covers all content types and pairs progress announcements with the actual work, with one completion per operation in the console and logs.
  • DAT Discovery keeps overall progress stable, shows the current file and activity separately, and uses clearer start and completion messages. File activity and counts are recorded consistently in the run, detail and debug logs.
  • Platform Preparation announces its working phases, shows file-checking and reading progress, and presents a concise result with elapsed time. TaskBar completion messages use 'TaskBar Completed:' in console output and logs, with the standard green success icon in the console and task identifiers in logs.
  • Nuclear cleanup verifies that database files are no longer in use before deleting any cleanup items, blocks new database readers during deletion, and reports underlying file-service errors with the number of items already deleted.
  • Completeness processes existing-output lookups faster when appending to a collection, while preserving output matching, duplicate handling and Clear behavior.
  • Scan Preparation retains successfully processed nested archive files in the workspace alongside their extracted contents, recording identities during transfer so Matching can recognize archive members required by multi-file sets. Existing archive guards and depth limits still apply.
  • Workspace cleanup uses AlphaFS to reduce cleanup time while preserving the workspace folder, path safeguards and failure reporting. Scan Preparation startup and Organizer final cleanup show an elapsed-time spinner during counting and deletion, followed by one completion with the cleared count.
  • File Discovery pairs announcements with the actual work, reports source and existing-output counts with elapsed time, shows an elapsed-time spinner while finding source files, and gives one completion with the final file count. Archive inspection shows one overall TaskBar without child bars and one completion. File Discovery records archive member listings and identifies archives containing nested archives for Scan Preparation.
  • Scan Preparation archive extraction shows overall progress and completed-versus-expected file counts, including committed work on resume; final counts follow acceptance checks. Nested extraction shows batch progress and exact file counts for the current batch once its contents are planned, with a separate actual nested-file total at completion. Nested archive inspection shows archives checked against the pass total with elapsed time; current activity stays within the archive TaskBar while inspection results are validated and saved. File counters use the label 'Total Files Extracted'; the current-batch row identifies its scope. Detailed archive planning, file acceptance, recovery saving and committed scratch cleanup operations have paired starts and elapsed ends in the run, detail and debug logs, identified by batch, nesting pass and recovery source offset. Console output keeps concise phase announcements, current activity and single TaskBar completions. Its summary omits the Scan Input section.
  • CHD preparation starts the next queued image whenever a worker becomes available, while preserving configured concurrency, result order and recovery behavior.
  • Scan Preparation records original and headerless file identities and creates headerless copies during copying and extraction; Matching verifies and reuses the prepared copies while preserving original bytes and raw-match priority. Missing or stale preparation evidence requires resuming Scan Preparation before Matching. Header normalization uses inclusive whole-file limits of 1,048,704 bytes for Atari 7800, 2,097,216 for Lynx, 134,218,256 for NES and 16,777,728 for SNES; larger files keep their original identity.
  • Supported CDI images use deferred track processing: Stage 5 fingerprints the source during decoding and hashes decoded tracks, avoiding a separate full-source preparation read. Track files are written only when output needs them. CDI images with external CD-TEXT retain their original container instead of publishing converted tracks.
  • Stages 1–10 and Reporting now resolve application information through database views over ingestion repositories. Stage 1–8 intermediate JSON files and their output templates are retired.
  • A complete clean restart is required. Move previous database and generated runtime state out of the active folders and rebuild from original inputs; existing databases are not migrated. Database schema remains 26.
  • Admin, End User and Quick Start guides explain the required clean restart, database-backed stage information, retired Stage 1–8 intermediate outputs, prepared identity reuse, nested archive retention, deferred CDI handling and current progress/cleanup displays. The Core API handbook is regenerated from current documentation metadata.
