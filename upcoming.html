CURATOR Planning Record

Planned Changes for Next Release

Updated On: September 15, 2026 at 6:22 PM EDT

What We're Working On

These are the improvements currently planned for the next CURATOR release. Development is still underway, so the final list may change before release.

MAME support in myOrganizer: CURATOR is a VERY EARLY, experimental implementation. It must NOT be relied upon as a proven means of organizing MAME sets. Continue using clrmame as the definitive MAME ROM manager.

Every BETA release requires a clean run. Databases, saved run state, and output plans from earlier BETA releases are not backward compatible.

Adding

  • Retaining MAME software-list disk declarations without treating logical disk hashes as physical ROM identities. Disk matching/output support remains experimental and incomplete; mixed ROM/disk sets stop explicitly.
  • Adding template-based mappings for DAT fields, keeping set names, descriptions, member filenames and checksums distinct.
  • Retaining declared MD5 checksums throughout DAT authority publication. Physical-file MD5 matching when SHA1 is absent remains deferred.
  • Adding independent language folders alongside geographic region folders, using the region and language mapping table.

Changing

  • Showing measured DAT, set and member counts during discovery, with stable platform context and clear process announcements. Reference preparation announces reuse checks, confirmation and summary loading; faster reuse is not established.
  • Placing all incomplete sets under one Incomplete Sets output folder, preserving the existing company, media-type and platform hierarchy.
  • Processing copy-only outputs first, followed by single-file ZIPs (including one-member sets), multi-file ZIPs and remaining conversions. Show the current output group, completed outputs and finishing steps more clearly.
  • Pacing copy and ZIP creation progress updates while retaining measured progress and completion reporting. A throughput improvement has not been established.
  • Speeding up Stage 9 destination planning while preserving output names, conflict handling, source records and every set membership. Destination checks remain current; the database does not assume files exist.
  • Refreshing the four guides for schema 22, complete-set deduplication, current review destinations and bounded Naomi/CDI support; remove obsolete software-list DTD setup instructions. Describe grouped Stage 10 progress, clarify database-owned recovery, and expand the Core API reference to 159 interfaces. Keep the latest guide PDFs included when preparing application packages.
  • Organizing the AtariMania ST catalogue into individual disk-image sets, retaining supporting documents and sidecars separately.
  • Simplifying unknown-file review destinations by removing the redundant Unresolved Media folder level.
  • Assigning DAT profiles from configured source-metadata rules instead of guessing from DAT filenames.
  • Naming set packages from the mapped authoritative set name while retaining declared member filenames inside each package.
  • Moving DAT authority processing into the database while retaining original definitions, source information, every set membership and rollback safeguards.
  • Preserving every DAT definition and set membership while sharing matching content using Size, CRC and SHA1, with MD5 compared when both declarations supply it. Filename comparison is case agnostic.
  • Removing the unused software-list DTD dependency.

Fixing

  • Allowing repeated DAT discovery to reuse unchanged results after a successful publication while later authority processing is still pending. Refreshing results when the current platform publication requires it.
  • Recognizing, during resumed Append work, ZIPs created by the current batch instead of treating them as leftovers from an earlier interrupted attempt.
  • Correcting preparation of certain DiscJuggler CDI data tracks, including decoded sector sizes and sector addresses. Remove a stored data-track pregap only when the resulting content matches a loaded authoritative DAT.
  • Recognizing Redump Sega Naomi disc sets and creating complete-set CHD output using the authoritative DAT filename.
  • Accepting optional game identifiers in XML DATs while keeping them separate from output filenames.
  • Recognizing redump.info publisher metadata alongside existing redump.org headers.
  • Deduplicating complete sets using their full member contents, then selecting the winning source through the configured authority hierarchy. Preserve distinct sets that merely share some files and retain all source declarations and memberships.
  • Preserving potential set members for content matching instead of excluding them solely by hidden status, extension, frontend-style names, system-style names or named empty archive entries.
  • Keeping Stage 10 progress rows stable, avoiding duplicate redraws and completing ZIP byte progress from receipt evidence.
  • Keeping DAT analysis progress in its taskbar instead of repeatedly displaying generic FileCopy completion messages.
  • Interpreting declared file sizes according to each DAT format and retaining their original declarations.
  • Correcting GoodTools Atari 2600 set names to match their ROM filenames without the final extension.
  • Avoiding unnecessary Conflicts output for equal content declared through different DAT names or formats, without losing definitions or memberships.
  • Avoiding false ambiguous matches caused solely by a missing MD5 declaration.
  • Keeping unbound review files separate under Unknown File, adding incremental suffixes when filenames collide.

Known limitations

  • CDI input support remains partial. The four tested Dreamcast CDI games do not form complete matched sets; this correction does not establish complete-game CHD output or repair differing audio.
  • Complete Redump Naomi sets have verified standalone CHD output with authoritative names. Creation of new RVZ files and converted-media collision/recovery cases still need acceptance testing; copying an existing RVZ does not establish conversion support.
  • Locked platform files may produce a generic error; release the file lock before rerunning preparation.
