Upcoming Changes

Updated On: August 30, 2026 at 1:10 PM EDT

What We're Working On

These are the improvements currently planned for the next CURATOR release. Development is still underway, so the final list may change before release.

Adding

  • Adding durable Stage 2 per-file DAT/XML fingerprints and physical-source-to-authority lineage for incremental ingestion and additive absent-source retention.
  • Adding persistent Stage 1 per-source authority ledgers with stable identity, content fingerprints, source-name lineage, and additive absent-source retention.
  • Adding direct HyperList menu XML ingestion with complete catalog retention and deterministic CRC identity enrichment.
  • Adding the CURATOR-created Atari ST Atarimania GameBase authority DAT to the required application authority set.

Changing

  • Changing Stage 2 so unchanged sources parse zero files, one added or changed source parses one file, absence parses zero files while retaining authority, and all execution paths report reconciled source-ledger counters.
  • Changing Stage 1 so it remains rerunnable after Stage 4 and later collection state exists, while preserving all later-stage state and authority.
  • Changing Stage 1 MAME -listxml recognition to use bounded root evidence and stable Arcade authority without parsing machine records.
  • Changing Stage 3 DAT-contract acquisition to use one ordinally ordered relational reader while preserving the existing Core.Database contract and deterministic authority results.
  • Changing Stage 5 extracted-file CRC32/SHA-1 hashing to use the configured 7z.dll native hash service while preserving the established one-pass file stream, optional SHA-256, normalization, progress, and output contracts.

Fixing

  • Fixing operator-guide explanations so the approved Stage 10 direct-CHD copy exception, configured-Input path verification, source preservation, and Input-availability requirement are clear to end users.
  • Fixing Stage 9 candidate identity and carry-forward path checks so post-Stage 4 planning reads only the configured workspace or CURATOR-owned temporary material and never reuses the Stage 4 input source as a working authority.
  • Fixing collection-manifest branding to publish the official application name myOrganizer: CURATOR.
  • Fixing collection progress so Stages 1-3 remain independent, Stage 4 alone confirms clean-slate replacement, Stage 5 recovery remains independent, Stage 6 refreshes the current DAR basis, and completed Stage 10 plans cannot execute again.
  • Fixing Redump DAT replacement safety by validating stable publisher identity, pinned DAT/CUE identities, complete CUE membership, and exact CUE content before Stage 2 ingestion or reuse.
  • Fixing official MAME software-list recognition to accept W3C-valid XML 1.0 declaration quoting and optional encoding while preserving required DOCTYPE, root, DTD, and full validation checks.
  • Fixing otherwise-complete non-Redump optical sets with a missing CUE so one unambiguous track-identical recovered Redump descriptor can enter the established universal CUE rewrite and generation pipeline, with provisional source readiness reconciled only after proven final materialization.
  • Fixing direct CHD handling so already-valid source CHDs are preserved by copy instead of being routed through CUE-led reconstruction.
  • Fixing menu-driven Stage 9 NO-GO handling so the Gateway exits directly to PowerShell, and restoring the Organize preset's final Stage 10 pre-summary acknowledgement without adding pauses between earlier stages or after the Stage 10 summary.
  • Fixing Atari 2600 HyperList authority names to use game/@name instead of description text containing Windows-invalid characters.
  • Fixing successfully traversed raw-unmatched embedded archives so their containers do not become duplicate NeedsAttention outputs while extracted descendants retain independent matching and review decisions.
