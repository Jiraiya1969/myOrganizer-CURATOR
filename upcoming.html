CURATOR Planning Record

Planned Changes for Next Release

Updated On: September 16, 2026 at 6:13 PM EDT

What We're Working On

These are the improvements currently planned for the next CURATOR release. Development is still underway, so the final list may change before release.

MAME support remains very early and experimental. Do not rely on myOrganizer: CURATOR to organize MAME sets. Continue using clrmame to manage your MAME collection.

Start a clean run with every BETA release. Saved databases and unfinished runs from an earlier BETA release cannot be reused.

Adding

  • Adding Operating System and Revisions folders within each platform's existing folder structure. Operating-system revisions go under Operating System\Revisions. Existing output folders are not automatically moved or renamed.
  • Adding recognition of multi-disk sets, disk sides, parts and companion files while keeping separate editions distinct.
  • Adding separate language folders alongside geographic region folders.
  • Adding guidance in the guides that antivirus software can interfere with DolphinTool and that you should allow it through the antivirus prompt to continue.

Changing

  • Showing clearer startup, scanning and output progress, including the current platform, file counts and completed work.
  • Placing incomplete sets under one Incomplete Sets folder while keeping their company, media and platform folders.
  • Copying files first, then creating ZIP packages and converting disc images, with clearer progress for each group.
  • Reducing the time spent planning output destinations while preserving filenames and checking for conflicts.
  • Updating the guides to explain duplicate handling, review folders, output progress and supported disc formats.
  • Organizing the AtariMania ST catalogue into individual disk-image sets, with supporting documents kept separately.
  • Simplifying review folders by removing the extra Unresolved Media level.
  • Naming packages after the set name in the selected DAT while preserving the filenames inside each package.
  • Removing the need for a separate software-list DTD file during setup.

Fixing

  • Correcting game names in supplied GameBase DATs that contain characters unsuitable for filenames.
  • Reusing unchanged DAT discovery results when repeating discovery.
  • Recognizing ZIPs already created when resuming an interrupted Append run.
  • Improving reading of some DiscJuggler CDI images.
  • Recognizing complete Redump Sega Naomi disc sets and producing CHD files with the names from the DAT.
  • Accepting DATs with optional game identifiers without adding those identifiers to output filenames.
  • Recognizing Redump DATs that use either redump.info or redump.org source information.
  • Removing duplicate complete sets according to your source preferences while keeping different sets that share some files.
  • Avoiding missed matches caused by hidden files, unusual filenames or file extensions.
  • Keeping progress displays stable and reducing repeated completion messages.
  • Reading file sizes correctly across supported DAT formats.
  • Correcting GoodTools Atari 2600 set names to match their ROM filenames without the extension.
  • Avoiding unnecessary Conflicts folders when different DATs describe identical content, including filenames that differ only in letter case.
  • Avoiding uncertain matches caused only by an omitted optional MD5 checksum in a DAT.
  • Keeping unidentified files separate under Unknown File and adding numbered suffixes when filenames collide.

Known limitations

  • Not every operating system or revision can be identified. Operating System folders currently depend on the Operating Systems category in TOSEC DATs. Revisions require a recognized revision label; a version number alone does not qualify.
  • Incomplete or uncertain media may be sent for review. Completeness checks depend on the available DAT information and cannot establish whether files omitted from a catalogue are required or whether a game is playable.
  • MAME software-list disc support is incomplete. Sets combining ROM files and disc images cannot currently be processed together.
  • CDI support is partial. Some images cannot produce a complete matched game or CHD, and differing audio is not repaired.
  • Copying existing RVZ files does not mean new RVZ files can be created. Conversion and recovery support remains limited.
  • Locked platform files may produce a generic error. Close the program holding the file before repeating preparation.
