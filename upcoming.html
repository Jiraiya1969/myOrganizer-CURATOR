CURATOR Planning Announcement

Planned Changes for a Future Release

What We're Working On

v2.0.0-beta.1 is the current public release. These are possible changes after that release. They are not live, released, promised, or guaranteed, and inclusion here is not evidence that an item is completed or approved for a future release.

Adding

  • Adding content-based Atari 8-bit Preservation and Atarimania GameBase authority profiles through the existing relational DAT contract.
  • Adding shared, verified Redump CUE recovery through Core.Secondary.
  • Adding official MAME software-list XML authority with matching-release DTD validation and Core-owned XML reading.
  • Adding a verified supplemental Atari Lynx Dragnet DAT with Fujiology, independent-header, and headerless identities.
  • Adding database-backed permanent collection manifests and retained reporting history.
  • Adding explicit Standard, Full Audit, Reconcile, and Detailed Export reporting actions.
  • Adding Reporting console announcements for new permanent collection items in the latest Organizer generation, including a platform breakdown.

Changing

  • Changing Stage 6 database planning to refresh bounded SQLite planner statistics immediately before set-based matching.
  • Changing Completeness multi-member classification to use authoritative set identity metadata.
  • Changing exact raw cross-platform hash collisions to publish every authoritative platform membership while retaining normalized ambiguity and existing duplicate preference.
  • Changing cartridge-header normalization to support signatures at explicit byte offsets.
  • Changing Reporting to derive current collection results from the permanent database record.
  • Changing Stage 10 and Reporting console messages to explain long-running work clearly.

Fixing

  • Fixing DAR publication for case-distinct set names and repeated same-name member occurrences.
  • Fixing otherwise-complete authoritative sets by materializing their one exact missing CUE descriptor through the shared Core operation.
  • Fixing MAME software-list size canonicalization and changed-authority replacement so hexadecimal XML sizes share exact identities with decimal DAT records and superseded DAR rows cannot remain active.
  • Fixing Stage 9 completion messaging so it confirms relational collection-plan commitment without claiming that an unwritten compatibility JSON file was saved.
  • Fixing incomplete authoritative CUE sets so exact DAR-matched pieces can complete one verified set regardless of their original source provenance.
  • Fixing unresolved NeedsAttention archives so original source provenance never contributes destination directory segments.
  • Fixing Atari Lynx and Atari 7800 matching by validating their platform-specific headers before removing them.
  • Fixing silent console periods during output preparation, manifest publication, and reporting reconciliation.
  • Fixing Stage 5 database publication for CUE descriptors whose referenced files are absent while retaining strict foreign-key protection for bound references.
  • Fixing Stage 5 loose-file SHA-1 identities by initializing incremental copy-hash providers before processing bytes.
  • Fixing zero-new-item collection manifests so Organizer and Reporting return an empty platform breakdown without failing.
  • Fixing Organizer Append totals so matching existing targets are counted as duplicates instead of newly written outputs while preserving their Official, Unofficial, or NeedsAttention classifications.
  • Fixing duplicate NeedsAttention payloads so one physical archive is planned per content identity while retaining every source occurrence as database evidence.
  • Fixing authority-matched output so DAR identity and set membership determine classification and packaging regardless of source provenance.
