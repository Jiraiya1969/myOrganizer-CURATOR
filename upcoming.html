CURATOR Planning Record

Planned Changes for Next Release

Updated On: September 21, 2026 at 1:13 PM EDT

What We're Working On

These are the improvements currently planned for the next CURATOR release. Development is still underway, so the final list may change before release.

MAME support remains very early and experimental. Do not rely on myOrganizer: CURATOR to organize MAME sets. Continue using clrmame to manage your MAME collection.

Start a clean run with every BETA release. Saved databases and unfinished runs from an earlier BETA release cannot be reused.

Adding

  • Adding newly found disks to their existing ZIP in Incomplete Sets during Append, while preserving existing contents and skipping disks already present. Completed containers remain in Incomplete Sets.
  • Adding folders for Applications, Educational software, Demos and other recognized catalogue categories within each platform, and Games folders within format-specific folders.
  • Adding Operating System and Revisions folders within each platform's existing folder structure. Operating-system revisions go under Operating System\Revisions. Existing output folders are not automatically moved or renamed.
  • Adding recognition of multi-disk sets, disk sides, parts and companion files while keeping separate editions distinct.
  • Applying language folders where appropriate while keeping USA-inclusive sets at the platform root regardless of language tags.
  • Simplifying the README and guide warning: antivirus software can interfere with DolphinTool. If DolphinTool reports the error, click OK to continue.

Changing

  • Showing overall progress and the current file separately while copying, packaging and converting files, with a consistent display while preparing disc images.
  • Using simple messages while clearing the existing collection output.
  • Starting collection stages through the Gateway, with Clear or Append chosen before processing begins.
  • Separating files without an identified set into recognizable content folders within needs_attention, including images, videos, disk images, programs and supporting files, while preserving their contents.
  • Showing clearer startup, scanning and output progress, including the current platform, file counts and completed work.
  • Placing incomplete sets under one Incomplete Sets folder while keeping their company, media and platform folders.
  • Copying files first, then creating ZIP packages and converting disc images, with clearer progress for each group.
  • Reducing the time spent planning output destinations while preserving filenames and checking for conflicts.
  • Updating the guides with current setup requirements, platform routing, duplicate handling, review folders, output progress and supported disc formats. Keeping only the latest guides in the documentation folder, with earlier editions available in History.
  • Organizing the AtariMania ST catalogue into individual disk-image sets, with supporting documents kept separately.
  • Simplifying review folders by removing the extra Unresolved Media level.
  • Naming packages after the set name in the selected DAT while preserving the filenames inside each package.
  • Removing the need for a separate software-list DTD file during setup.

Fixing

  • Avoiding an extra Games folder when a game has no format-specific destination, while preserving region and other category folders. Existing output is not automatically moved.
  • Allowing processing to continue when a log file is briefly busy; a file that remains unavailable can still stop the run.
  • Reducing repeated success messages when saving incomplete sets, while keeping details available in the log.
  • Clearing temporary working files more quickly and reporting when cleanup cannot finish.
  • Using Cracked as the folder label for recognized cracked variants in newly planned output.
  • Reducing delays when saving the final catalogue while preserving the ability to resume interrupted work.
  • Reducing interruptions caused by temporary difficulty opening the collection database for writing.
  • Resuming an interrupted scan from the Organize menu without rerunning File Discovery or clearing existing output.
  • Keeping fuller database failure details in stage logs and showing where to find them when Scan Preparation stops.
  • Restoring coloured messages and live progress when starting collection processing from the main menu, while keeping errors visible.
  • Keeping unidentified disc-image files under Unknown File instead of unrelated review folders.
  • Excluding only zero-byte files named exactly _ as placeholders.
  • Routing recognized alternate editions into a single Alternate Dumps folder without treating alternate status alone as an unofficial release, while preserving internal member directories inside ZIPs.
  • Placing single-file Beta and Unlicensed releases in the appropriate unofficial folders when that information is available in the selected DAT. Existing recognized classifications take priority.
  • Clearing previous output before a new Clear run starts, preventing old output from causing unnecessary Conflicts folders.
  • Preserving completed output when resuming an interrupted Clear or Append run.
  • Stopping final output when completeness checks find blocking issues, and reporting the stopped run accurately.
  • Keeping scan-preparation warning details available and avoiding misleading messages when an archive was processed successfully.
  • Fixing a completed preparation resume that could prevent collection planning from continuing.
  • Placing games, applications and other recognized software categories in their corresponding format folders, including Atari 8-Bit and Atari ST, while avoiding unnecessary Conflicts folders for different formats of the same title.
  • Correcting company and platform folders, including American Laser Games and ColecoVision, while keeping existing collection folders and package contents.
  • Fixing an error that could prevent a clean installation from creating its database.
  • Correcting game names in supplied GameBase DATs that contain characters unsuitable for filenames.
  • Reusing unchanged DAT discovery results when repeating discovery.
  • Recognizing ZIPs already created when resuming an interrupted Append run.
  • Converting supported DiscJuggler CDI images into individual BIN tracks and a matching CUE file while retaining the original images.
  • Checking converted tracks and disc layout before accepting the files, and stopping conversion when required disc information cannot be preserved.
  • Producing individual BIN tracks named after their original CDI and track number, with CUE references that resolve to the corresponding files. Preserving those relationships when unmatched optical files are sent for review, instead of separately ZIPping their tracks.
  • Avoiding unnecessary separate review copies of converted tracks when the original CDI matches the selected DAT. When it does not match, the converted files remain available for review.
  • Recognizing complete Redump Sega Naomi disc sets and producing CHD files with the names from the DAT.
  • Accepting DATs with optional game identifiers without adding those identifiers to output filenames.
  • Recognizing Redump DATs that use either redump.info or redump.org source information.
  • Removing duplicate complete sets according to your source preferences while keeping different sets that share some files.
  • Avoiding missed matches caused by hidden files, unusual filenames or file extensions.
  • Keeping progress displays stable and reducing repeated completion messages.
  • Reading file sizes correctly across supported DAT formats.
  • Correcting GoodTools Atari 2600 set names to match their ROM filenames without the extension.
  • Avoiding unnecessary Conflicts folders when different DATs describe identical content, including filenames that differ only in letter case.
  • Avoiding uncertain matches caused only by an omitted optional MD5 checksum in a DAT.
  • Keeping unidentified archive members separate and adding numbered suffixes within their review folders when filenames collide. Files without a recognized content type remain under Unknown File.

Known limitations

  • Not every operating system or revision can be identified. Operating System folders currently depend on the Operating Systems category in TOSEC DATs. Revisions require a recognized revision label; a version number alone does not qualify.
  • Incomplete or uncertain media may be sent for review. Completeness checks depend on the available DAT information and cannot establish whether files omitted from a catalogue are required or whether a game is playable.
  • MAME software-list disc support is incomplete. Sets combining ROM files and disc images cannot currently be processed together.
  • CDI support is limited to certain disc layouts. Some images may not convert correctly, and successful conversion does not guarantee that a game will run in an emulator or on original hardware.
  • Some NRG images cannot be converted because of unsupported disc information. MDS images cannot be processed if their companion data file cannot be opened. Audio differences are not repaired automatically.
  • Copying existing RVZ files does not mean new RVZ files can be created. Conversion and recovery support remains limited.
  • Locked platform files may produce a generic error. Close the program holding the file before repeating preparation.
