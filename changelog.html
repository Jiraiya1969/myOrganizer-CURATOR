CURATOR Release History

Changelog

A complete end-user record of improvements, fixes, and known limitations in every public CURATOR release.

v1.0.0-beta.5

August 3, 2026

Changed

  • Reporting now keeps operator-facing output concise while recording detailed milestones in DEBUG logs.
  • Physical-audit reconciliation now uses bounded summary and individual-review panels with Approve All, Review Each, Make No Changes, and Cancel; only approved findings alter manifests.
  • The guides now distinguish the intended boundary from beta.5 behavior: official and unofficial physical output is authoritative truth, while needs_attention is intended to be a separate review queue.

Fixed

  • Preserved original and immediate Reporting publication provenance through repeated transitive reuse.
  • Preserved complete multi-member DAR sets across multiple source containers during Stage 9 planning.
  • Corrected Core API handbook metadata so the application version is not presented as the component build.

Known limitations

  • Reporting_DEV_49 in beta.5 still processes needs_attention filesystem content and NeedsAttention manifest rows through classification, counting, summaries, and presentation. Full exclusion remains unresolved under DEFERRED-051.

v1.0.0-beta.4

July 31, 2026

Added

  • Added END_USER_LICENSE_AND_LEGAL_NOTICE.md as a required release deliverable with CURATOR-specific safety and legal notices that preserve all GPL-granted rights.
  • Added schema-v2 company manifests with final-artifact SHA-256 evidence and immutable existing-record behavior during Append.
  • Added Gateway option V for an explicit full physical SHA-256 collection audit with operator-reviewed manifest reconciliation.

Fixed

  • Suppressed internal latest_status.json read messages so refreshed Gateway menus and confirmation screens start with a clean application header.
  • Corrected Stage 7 validation of contextual CHD/CUE authority matches so current AuthorityProvenance DAT evidence is accepted without weakening missing-evidence or authority-integrity checks.
  • Closed the selected-run pause correction after operator confirmation of the remaining acknowledgement-order paths.

v1.0.0-beta.3

July 30, 2026

Changed

  • Added a standalone LICENSE file containing the complete GNU General Public License version 3 text.
  • Stage 5 now reports exact, visible progress while classifying and verifying large source inventories.
  • Stage 6 now reports exact counts while hashing, preparing results, serializing records, and verifying output, with less unnecessary console rendering.
  • Stage 7 removes repeated validation scans and reports exact progress through validation and publication.
  • Stage 8 reuses validated authority membership data, removes repeated scans, and reports exact progress through assembly and publication.
  • Large Stage 8 assembly runs now complete substantially faster while preserving the same normalized result.
  • Stage 9 reports exact progress while avoiding redundant routing, receipt, and source-path preparation.
  • Stage 10 validates planned sources beneath authorized roots and leaves missing-source detection to the physical operation that consumes each source.
  • The End User Manual and Quick Start Guide now recommend current clrmame for complete MAME-native ROM-set management while noting that legacy clrmamepro remains available.

Fixed

  • Fixed long Stage 8 intervals that previously had no visible console reporting.
  • Fixed Stage 8 final JSON progress so it reflects selected membership and review records before output verification.
  • Added the missing blank line above the final stage resource-release message.
  • Adjusted selected pause-enabled Gateway options 4, 6, and 8 to suppress a redundant post-summary pause while retaining their summary and final Gateway acknowledgement.
  • Regenerated the Core API Developer Handbook so headings and emphasis render normally.
  • Corrected the End User Manual cover version and document-update date.
  • Removed Stage 10 planning-time source existence probes and the large source-tree preflight without changing output planning or destination safety checks.

Known limitations

  • Binmerge build provenance and redistribution evidence for eleven cue/GDI ZIP packages remain unresolved under DEFERRED-038.

v1.0.0-beta.2

July 28, 2026

This beta focuses on faster preparation of large collections, safer recovery, clearer progress reporting, and documentation that is easier to use and keep with the application.

Added

  • Added a changelog to the application folder so each release clearly explains what changed.
  • Added stronger release-package checks against the approved application inventory, excluding development, temporary, and operator-owned files.
  • Added CURATOR-owned Atari 8-Bit and Atari ST routing definitions for a ready-to-use installation. Operator-supplied platform and DAT files remain outside the package.

Changed

  • Large Stage 5 preparation jobs now copy ordinary files and process archives in controlled parallel groups for substantially faster, predictably ordered preparation.
  • Stage 5 recovery records are written more efficiently, reducing repeated bookkeeping for collections containing thousands of files.
  • Archive progress is smoother and less noisy, with one continuous display covering the complete workload.
  • Matching passes the exact verified game data forward when supported normalization was needed to establish the match.
  • The Admin Guide, End User Manual, Quick Start Guide, and Core API Developer Handbook are now supplied as PDF files.
  • The developer handbook now documents all 144 current Core programming interfaces.

Fixed

  • Fixed Stage 5 archive preparation when the selected Workspace folder is outside the CURATOR application folder.
  • Fixed interrupted archive recovery so unfinished results are removed before retrying while already committed files remain protected.
  • Fixed empty or unusable archives so they can be reported and skipped without ending the entire preparation stage.
  • Fixed Stage 5 error reporting so the original problem remains visible even after logging services close.
  • Fixed supported disc matching when cue-sheet and track evidence is required.
  • Fixed later stages receiving the original file instead of the normalized data that established an authoritative match.
  • Added a clear, safe cancellation path to both advanced Nuclear cleanup confirmations; only the exact phrase performs cleanup.
  • Fixed the completion screen shown after generating the Core API handbook.

Known limitations

  • In a pause-enabled multi-stage Gateway run, the final selected stage may not show its promised acknowledgement before the separate overall timing summary. Both results are still produced.
  • A very large interrupted Stage 5 recovery record can delay Gateway startup while CURATOR validates saved work before showing the main menu.

v1.0.0-beta.1

July 26, 2026

Added

  • Published the first public beta of CURATOR.
  • Added guided Prepare DAR, Organize, and Reporting workflows for LaunchBox-compatible collections.
  • Added platform and DAT discovery, authority preparation, source discovery, staging, matching, DAT validation, assembly, completeness analysis, physical organization, and reporting.
  • Added authority-based processing of loose files and supported archive and disc-image workflows.
  • Added recoverable staging and output transactions that can resume from valid committed progress.
  • Added Clear and Append destination choices.
  • Added visible progress, structured logs, validation evidence, and final collection reports.
  • Included an Admin Guide, End User Manual, Quick Start Guide, and Core API Developer Handbook.
  • Added path safeguards separating source, output, working, and application folders.

Known limitations

  • In pause-enabled Gateway sequences, the final selected stage may not show its promised acknowledgement before the separate Gateway timing summary. The timing summary is still produced.
